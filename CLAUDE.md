# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

This is the Docker stack that runs **Triple Performance** (a MediaWiki-based wiki) and **Itinera** (a
custom Next.js app), plus a number of supporting services. It does not contain MediaWiki's own source
code — instead `bin/build_project.php` clones MediaWiki core and a curated list of extensions/skins into
`html/`, a directory that is git-ignored and rebuilt on demand.

- `html/` and `insights/` are git-ignored — they are generated by `build_project.php` / cloned separately, never edit tracked files there expecting them to persist under version control here.
- `itinera/` is a separate git repositories checked out inside this one (Itinera's Next.js app, developed in its own context). Don't treat them as part of this repo's history/diffs.
- `insights/` is another external repo (github.com/neayi/insights), cloned as a sibling checkout, not vendored here. Insights is the authentication service for TriplePerformance (through the extension `neayi_auth`)

## Repo layout

- `html/extensions` - where the specific extensions live (as well as a few standard and possibly forked extensions)  
- `html/skins/skin-neayi` - the skin for Triple Performance
- `bin/build_project.php` — the core provisioning script. Defines the full list of MediaWiki extensions/skins (with git URL, branch, and whether they need `composer` or `submodules` post-install) and clones/updates them into `html/`. Run via `wiki.php build_project.php` (see below), never directly with plain `php`.
- `wiki.php` — dispatcher for running MediaWiki maintenance scripts and DB operations against a target environment (`--dev` / `--prod` / `--preprod`) and language (`--fr`, `--en`, ... or `--all-languages`). Wraps `docker compose exec/run` so you don't call docker compose by hand for these tasks.
- `config/` — `LocalSettings.php`, namespace config, `robots.txt`. Symlinked into `html/` by `build_project.php` (`linkWikiSettings`), so edit the files here, not the symlinks inside `html/`.
- `engine/` — Dockerfiles/configs per service: `php_server/` (Apache+PHP+msmtp), `traefik/` (reverse proxy + dev certs), `mysql/`, `n8n/`.
- `backup/` — DB backup/restore scripts (`backup.sh`, `load-db.sh`, `load-prod-db.sh`, `clear_old_backups.sh`) and SQL dumps under `backup/DBs/`. Needs `backup/.mysql.cnf` (git-ignored) with the root MySQL password.
- `bin/sql/` — SQL files consumed by `load_db.sh` when creating a fresh DB (`bin/sql/wiki.sql`, migration SQL such as `UpgradeTo1.43.sql`). Prod DB dumps go in `bin/sql/wiki_prod.sql` (git-ignored, not created by default).
- `docker-compose.yml` / `docker-compose.prod.yml` — dev/preprod vs. production compose files. Dev key services: `traefik`, `web`, `insights_php`, `itinera`, `insights`, `db`, `redis`, `elasticsearch`/`elasticvue`, `piwigo`, `matomo`, `n8n`, `qdrant`, `pdf-to-image`, `chrome-headless`, `itk-info`, `postgres`, `dbgate`. The prod compose additionally splits `web`/`web_maintenance`/`web_preprod` and `insights`/`insights_preprod`, and adds `portainer`.
- `geoip/` — houses the `geoblock` repo (cloned separately, not vendored) used for geo-blocking rules in Traefik.

## Common commands

All PHP entrypoints run through Docker; there is no local PHP toolchain expected, appart for using wiki.php.

**Bring the stack up**
```
docker compose up --build -d
```
The local docker-compose.yml skips a few container that are not critical to the everyday dev environment and should be started manually when necessary (profile full: piwigo, matomo...).


## Architecture notes

- **Extension/skin manifest lives in code, not config.** `getWikiComponents()` in `bin/build_project.php`
  is the single source of truth for which MediaWiki extensions/skins are used, their upstream git repo,
  branch/tag, and whether they need a composer install or submodule init after cloning. To add, remove,
  or repin an extension, edit that function — don't hand-edit anything under `html/extensions`, since
  that whole tree is disposable and regenerated by `--create-env`/`--update`.
